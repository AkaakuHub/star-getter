# ラブギャザーのライブ処理

30秒間のミニゲームです。強化・育成はありません。ライブ中の効果は次のライブへ引き継ぎません。

## 移植した処理

本家の`clientScore.ts`、`clientScoreInput.ts`、`heartRank.ts`、`heartRuntime.ts`、`heartPresentation.ts`、`genesisSkill.ts`から、得点、ランク、ハートの生成・寿命・回収・描画、開花ゲージの計算関数を移植しています。プロジェクト名をラブギャザーへ変更し、ファイルを責務ごとに分割しています。

- 各カードのスマイル・ピュア・クールからアピール値を計算します。現在の楽曲は全属性一致として各属性を1.5倍にし、楽曲秒数と1000で割ります。
- 正規化したアピール値の平均×120000を切り捨て、回収数、ハートランク、LOVE補正を掛けます。
- ハートランクは回収数×ボルテージLv.を100・200・360・720で区切り、倍率を1・2・2.5・3・3.5とします。
- LOVE増加効果は加算します。開花プログレスの1.5乗も同じ補正へ加算し、10000分率で評価します。
- 本家と同じFloat32変換、浮動小数点演算と切り捨てを維持します。合計得点はBigIntで保持します。
- 回収回数だけによる10倍連鎖や、クライマックスだけの独自倍率はありません。
- 基礎点は本家の回収計算を使用します。その後、ラブギャザーの成長倍率をBigIntで乗算します。最終得点は本家の整数上限では止めず、9999無量大数を上限とします。寿命切れ・溢れた追加分も本家の消滅回収を基礎点として計算します。
- 効果増幅は加算します。50%を2回使用した場合は100→150→200です。
- ハートは100個まで保持します。起動画面で表示上限を10〜100個から10個刻みで選択し、既定は100個です。表示しない分は個数と寿命だけで管理し、得点・回収特性・カード循環を維持します。
- 待機位置はXが-5.5〜5.5、Yが-1.5〜0.5です。そこから0.8〜1.2下の位置で出現し、0.45〜0.55秒かけて指数減速で飛び出します。待機中の落下・点滅・回収後の移動も移植した関数で計算します。
- ハートの基準寿命は楽曲時間の1/12です。30秒ライブでは2.5秒になります。

## 画面配置

1080×1920を基準にします。メンタルは下部左、APは下部右、ボルテージはその上です。ハート個数は保存済みの文字領域を使用し、追加の背景を重ねません。一時停止ボタンは利用者の指定に従い左側中央に配置します。効果文は中央下部の黒い半透明固定枠です。

## 検証

`tests/game/clientScore.test.ts`は本家の計算例と、カード未使用の放置・回収のみの30秒プレイを確認します。`tests/game/heartRuntime.test.ts`は生成範囲、表示数、飛び出し、回収後の個数と移動を確認します。`tests/game/playBalance.test.ts`は同じ初期編成でカード効果と回収の組み合わせを比較します。

## ハート描画

Canvas1枚へ描画し、Lucideのハート・フラワーを一度だけ画像化して再利用します。DOMやSVGをハートごとに生成しません。フレームレートや解像度倍率に独自の上限を設けず、requestAnimationFrameとデバイスの画素密度に従います。一時停止・終了中は連続描画を止めます。位置・透明度・回収移動は移植した計算関数を使用し、ゲーム内の時刻更新は60Hzのまま維持します。

表示数は記録・編成とは別のlocalStorageキーへ保存します。`tests/game/heartDisplay.test.ts`で表示数10・50・100の30秒プレイ結果が一致することを検証します。

## 複利成長と評価

成長カードの「花咲くノート」「光のプリズム」「リボンの祝福」は、現在の成長倍率を100万倍にします。倍率はライブ開始時に1から始まり、再使用するたびに乗算します。成長倍率を使わない基礎点や、回収回数だけの加点倍率は変更しません。

評価は全楽曲共通で、Cが1京未満、Bが1京以上、Aが1極以上、Sが1那由他以上、SSが1無量大数以上、SSSが9999無量大数到達です。83万700はCです。

`tests/game/growth.test.ts`で複利、BigIntの下位桁、評価境界を検証します。`tests/game/playBalance.test.ts`は、初期編成で毎秒2回のカード使用・毎秒3回の回収・SPを組み合わせた30秒ライブが、3種類の乱数seedで目標へ到達することを検証します。
